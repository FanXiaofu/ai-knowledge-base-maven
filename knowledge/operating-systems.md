# 操作系统技术知识库

## 操作系统是什么

操作系统是管理计算机硬件和软件资源的系统软件，为应用程序提供运行环境。

操作系统的核心职责：进程管理、内存管理、文件系统管理、设备管理和提供系统调用接口。

## 进程与线程

进程是资源分配的基本单位，拥有独立的内存空间；线程是 CPU 调度的基本单位，同一进程内的线程共享进程的内存和资源。

进程切换开销大，需要切换页表和刷新缓存；线程切换开销小，但共享内存带来并发安全问题。

协程是用户态的轻量级执行单元，切换完全在用户空间完成，开销比线程更小，适合高并发 IO 场景。

## 进程间通信

常见进程间通信方式：

1. 管道，单向字节流，适合父子进程；
2. 消息队列，内核中的消息链表；
3. 共享内存，速度最快的 IPC 方式，需要配合同步机制；
4. 信号量，用于进程同步；
5. 套接字，支持跨主机通信。

## 死锁

死锁指多个进程互相等待对方持有的资源，导致永久阻塞。

死锁的四个必要条件：互斥、持有并等待、不可剥夺、循环等待。

破坏任意一个条件即可预防死锁，最常用的是按固定顺序申请资源来破坏循环等待。

## 内存管理

内存管理的目标是为进程分配独立的地址空间，并高效利用物理内存。

虚拟地址空间让每个进程认为自己独占内存，通过 MMU 将虚拟地址转换为物理地址。

页是内存管理的基本单位，常见大小 4KB，页表记录虚拟页到物理页的映射，TLB 缓存页表项加速地址转换。

## 虚拟内存

虚拟内存利用磁盘扩展可用内存，暂时不用的页面换出到磁盘，需要时再换入。

缺页中断指访问的页面不在物理内存中，操作系统从磁盘加载页面后重新执行指令。

常见页面置换算法：FIFO、LRU、Clock。LRU 根据局部性原理优先淘汰最久未使用的页面。

## 文件系统

文件系统负责管理持久化存储，核心概念是 inode：记录文件的元数据和数据块位置，文件名只是 inode 的别名。

硬链接指向同一个 inode，不能跨文件系统；软链接是独立文件，保存目标路径。

写文件时先写日志再写数据的日志型文件系统，可以在断电后快速恢复一致性。

## IO 多路复用

IO 多路复用让单个线程同时监听多个文件描述符的就绪事件。

三种实现：select 用固定大小的位图，每次调用都要全量拷贝和遍历；poll 改用链表突破数量限制；epoll 通过红黑树注册描述符、就绪链表返回事件，支持海量并发连接。

Redis、Nginx 等高性能服务都基于 epoll 实现事件驱动模型。

## 零拷贝

传统文件传输需要四次拷贝和四次上下文切换。

零拷贝通过 sendfile 等系统调用减少数据在内核空间和用户空间之间的冗余拷贝，显著降低 CPU 开销。

Kafka 和 Nginx 利用零拷贝提升文件传输性能。

## 用户态与内核态

内核态可以执行特权指令、访问全部内存；用户态受限，必须通过系统调用陷入内核态才能访问受保护的资源。

频繁的系统调用和上下文切换有性能开销，减少系统调用次数是很多性能优化的出发点。

## 缓冲与缓存

缓冲用于协调不同设备或进程之间的速度差异，例如写磁盘前的缓冲区合并小 IO。

缓存用于保存热点数据副本，利用局部性原理加速访问。

缓冲区和缓存可能合并在同一块内存中，例如 Linux 的 Page Cache 既缓存文件数据也缓冲写操作。
