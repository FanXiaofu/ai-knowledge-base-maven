# Redis 技术知识库

## Redis 是什么

Redis 是一个开源的内存数据结构存储系统，可以作为数据库、缓存和消息中间件使用。

Redis 的主要特点是基于内存进行数据读写，因此具有较低的访问延迟和较高的吞吐能力。

## Redis 数据类型

Redis 常见的数据类型包括：

1. String
2. Hash
3. List
4. Set
5. Sorted Set

其中 String 是最常用的数据类型，可以用于缓存对象、计数器、分布式锁等场景。

## Redis 持久化

Redis 主要提供 RDB 和 AOF 两种持久化机制。

RDB 是在指定时间间隔内生成 Redis 数据集的快照，恢复速度较快，但可能丢失最近一次快照之后的数据。

AOF 通过记录 Redis 的写命令实现持久化，数据完整性通常高于 RDB，但文件体积和恢复成本可能更高。

## Redis 缓存

在 Java 后端系统中，Redis 经常用于缓存热点数据。

典型流程是：

用户请求首先查询 Redis，如果缓存命中则直接返回；

如果缓存未命中，则查询数据库，将查询结果写入 Redis，然后返回结果。

这种方式可以减少数据库访问压力，提高系统整体吞吐能力。

## Redis 缓存穿透

缓存穿透是指大量请求查询一个不存在的数据，导致请求直接访问数据库。

常见解决方案包括：

- 缓存空对象
- 布隆过滤器

## Redis 缓存击穿

缓存击穿通常发生在某个热点 Key 过期的瞬间，大量并发请求同时访问数据库。

常见解决方案包括：

- 互斥锁
- 逻辑过期
- 热点数据永不过期

## Redis 缓存雪崩

缓存雪崩是大量缓存 Key 在同一时间失效，导致大量请求同时访问数据库。

常见解决方案包括：

- 设置随机过期时间
- 服务降级
- 限流
- 多级缓存

## Redis 分布式锁

Redis 可以利用 SET 命令实现分布式锁。

分布式锁可以用于控制多个服务实例对共享资源的并发访问。

实现分布式锁时需要考虑锁的原子性、过期时间以及误删锁等问题。
## Redis 主从复制

Redis 通过主从复制实现数据冗余和高可用。

从节点首次连接主节点时会进行全量同步，主节点生成 RDB 快照发送给从节点；之后主节点将写命令增量传播给从节点。

主从复制是读写分离的基础，读请求可以由从节点分担，写请求仍然由主节点处理。

## Redis 哨兵

哨兵是 Redis 高可用解决方案，负责监控主节点状态并在主节点故障时自动完成故障转移。

哨兵集群通过相互确认判定主节点客观下线，然后选举领头哨兵，在从节点中挑选新主节点并通知客户端新的访问地址。

## Redis 集群

Redis 集群将数据划分到 16384 个哈希槽，每个节点负责一部分槽位，实现数据分片和水平扩容。

客户端访问的 Key 通过 CRC16 计算哈希槽，直连负责该槽位的节点。

集群模式下多 Key 操作要求所有 Key 落在同一个槽，可以使用 Hash Tag 让相关 Key 分配到同一节点。

## Redis 大 Key 与热 Key

大 Key 指 Value 过大的 Key，例如百万成员的集合，会导致网络拥塞、删除阻塞和迁移困难。

热 Key 指访问频率极高的 Key，单节点容易成为性能瓶颈。

治理手段包括拆分大 Key、本地缓存热点数据、对热 Key 增加副本和随机后缀打散。
