# AI 应用开发技术知识库

## 大语言模型是什么

大语言模型是基于 Transformer 架构、在海量文本上预训练的深度学习模型，能够理解和生成自然语言。

大语言模型的工作方式是：根据上下文逐个预测下一个 Token，直到生成完整回答。

模型的参数规模从几 B 到几百 B 不等，通常参数越大能力越强，但推理成本也越高。

## Token 与上下文窗口

Token 是大语言模型处理文本的基本单位，一个汉字或一个英文单词通常对应一个或多个 Token。

上下文窗口是模型一次能处理的最大 Token 数量，包括用户输入、历史对话和系统提示的总和。

上下文窗口有限，因此长文档通常需要切分后通过检索的方式按需提供给模型，而不是全部塞进提示词。

## Prompt 工程

Prompt 工程是通过设计提示词来引导模型输出预期结果的技术。

常用技巧包括：

1. 给模型设定角色，例如"你是一个企业知识库问答助手"；
2. 提供清晰的约束和输出格式要求；
3. 提供少样本示例；
4. 思维链，引导模型分步推理；
5. 明确告知模型知识不足时应该如何回答。

Prompt 中提供的事实性上下文称为 Grounding，可以有效减少模型编造内容。

## Embedding 是什么

Embedding 是将文本映射为高维稠密向量的技术，语义相近的文本在向量空间中距离更近。

文本经过 Embedding 模型后变成一个固定长度的向量，例如 1024 维，向量的相似度通常用余弦距离或内积衡量。

Embedding 是语义检索的基础：把文档和查询都向量化，就能用向量距离找出语义最相关的文档片段。

## 向量数据库

向量数据库专门用于存储和检索向量数据，核心能力是高维向量的近似最近邻搜索。

常见索引算法是 HNSW，一种基于图的近似最近邻索引，查询速度快、召回率高，但构建成本和内存占用较高。

常见的相似度度量：余弦距离、欧氏距离、内积。

PGVector 是 PostgreSQL 的向量扩展，可以让业务数据库同时承担向量存储，部署和运维成本低。

## RAG 是什么

RAG 即检索增强生成，是知识库问答的主流架构。

RAG 的完整流程：

1. 文档导入：解析文档，切分为 Chunk，向量化后写入向量库；
2. 检索：将用户问题向量化，从向量库召回相关 Chunk；
3. 生成：将检索到的内容作为上下文，让大模型基于上下文回答问题。

RAG 的价值：让模型使用私有的、实时的知识，回答可溯源，显著减少幻觉，且不需要重新训练模型。

## 混合检索

向量检索擅长语义匹配，但对专有名词、编号、代码等精确关键词不敏感。

BM25 是经典的词频检索算法，考虑词频、逆文档频率和文档长度归一化，擅长精确关键词匹配。

混合检索将向量检索和 BM25 检索的结果融合，取长补短。

RRF 即倒数排名融合，是最常用的融合算法，每个文档的得分为它在各路结果中排名倒数的和，公式为 score = sum(1 / (K + rank))，K 通常取 60。

## 重排序

初筛阶段（向量检索、BM25）为了速度通常使用双塔结构，精度有限。

重排序模型使用交叉编码器，把查询和文档拼在一起逐对打分，精度更高但更耗时，因此只用于对少量候选文档精排。

典型的 RAG 检索链路：多路召回 Top 20~50，粗排融合到 Top 5~10，重排序选出 Top 3，再交给大模型生成。

## RAG 幻觉与拒答

幻觉指模型生成看似合理但不符合事实的内容。RAG 通过提供真实上下文抑制幻觉，但不能完全消除。

拒答机制是知识库问答的重要环节：当检索结果与问题的相关度低于阈值时，系统直接回答知识库中没有足够的信息，而不是让模型强行回答。

拒答阈值需要用标注数据集校准，在精确率和召回率之间权衡；知识库内容变化后应重新校准。

## Agent 是什么

Agent 是能够感知环境、自主决策并调用工具完成任务的智能体。

Agent 的基本循环：接收目标、思考规划、调用工具、观察结果、继续决策，直到完成任务。

ReAct 是经典的 Agent 模式，交替进行推理（Reason）和行动（Act）。

## 工具调用

工具调用是让大模型与外部系统交互的机制：开发者向模型描述可用的工具名称、功能和参数 Schema，模型决定何时调用哪个工具并生成参数。

工具调用的典型场景：查询知识库、查询数据库、调用第三方 API、执行计算。

模型只负责决定调用和生成参数，实际执行由应用代码完成，执行结果再返回给模型继续推理。

## 模型微调

微调是在预训练模型基础上，用领域数据继续训练，让模型掌握特定风格或知识。

常见微调方式：全参数微调成本高，LoRA 等参数高效微调只训练少量附加参数，成本低效果好。

微调与 RAG 的选择：微调适合改变模型的风格、格式和领域能力；RAG 适合注入动态变化的知识。两者可以结合使用。

## LLM 应用评估

LLM 应用评估包括模型能力评估和业务效果评估。

RAG 检索质量常用指标：命中率、MRR、NDCG，衡量正确文档是否被召回以及排名是否靠前。

生成质量常用评估维度：忠实度，答案是否忠于检索内容；相关性，答案是否回答了问题。

构建验证集是评估的基础：标注问题和标准答案，每次调整检索参数或阈值后回归评估，用数据驱动优化。

## 模型部署

大模型本地部署常用 Ollama、vLLM 等工具。

Ollama 使用简单，适合个人开发和中小规模场景，通过 REST API 提供对话和向量化能力。

选择模型时需要权衡参数规模、显存占用、响应速度和效果，小参数量化模型在消费级硬件上可以流畅运行。

Embedding 模型选型考虑维度、语言支持、最大长度和检索效果，中文场景常用 BGE 系列模型。
