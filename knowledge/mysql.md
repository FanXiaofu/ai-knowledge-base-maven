# MySQL 技术知识库

## MySQL 是什么

MySQL 是一种开源的关系型数据库管理系统，使用 SQL 语言进行数据管理。

MySQL 广泛应用于 Web 应用和企业级后端系统。

## MySQL 索引

索引是一种用于提高数据库查询效率的数据结构。

常见索引类型包括：

- B+Tree 索引
- Hash 索引
- 联合索引
- 唯一索引

InnoDB 默认使用 B+Tree 索引。

## MySQL 事务

事务需要满足 ACID 特性：

- Atomicity：原子性
- Consistency：一致性
- Isolation：隔离性
- Durability：持久性

## MySQL 隔离级别

MySQL InnoDB 支持：

- READ UNCOMMITTED
- READ COMMITTED
- REPEATABLE READ
- SERIALIZABLE

MySQL 默认隔离级别是 REPEATABLE READ。


## B+Tree

B+Tree 是一种多路平衡查找树，是 InnoDB 索引底层默认的数据结构。
所有数据记录都存放在叶子节点，非叶子节点只存储索引键值，用于索引导航。
叶子节点通过双向链表串联，非常适合范围查询与排序操作。
磁盘 IO 次数少，查询性能稳定。

## 联合索引

联合索引也叫复合索引，是对表中多个字段建立的索引。
索引树按照索引字段定义顺序排序存储。
联合索引遵循最左匹配原则。
可以减少回表，适合多字段条件查询场景。

## 最左匹配原则

最左匹配原则是联合索引的匹配规则。
查询时会从联合索引最左侧字段开始依次匹配，当联合索引的某一列出现范围条件时，通常会影响后续列参与索引范围定位的能力，但后续列仍可能用于索引条件下推等过滤。
where 条件需要匹配索引最左列才能走上联合索引。
调整查询条件字段顺序，不会改变索引匹配逻辑，由索引定义顺序决定。

## 索引失效

索引失效指 SQL 无法使用已建立的索引，退化为全表扫描。
常见失效场景：

- 索引列使用函数、运算、隐式类型转换
- like 以通配符开头 `%xxx`
- 违背最左匹配原则
- or 一侧字段无索引
- MySQL 优化器判断全表扫描比索引更快，主动放弃索引。

## 覆盖索引

覆盖索引：查询所需要的全部字段数据，都可以直接从索引中获取，不需要回表读取主键再访问聚簇索引行数据。
Explain 输出 Extra 字段显示 `Using index` 代表命中覆盖索引。
可以消除回表 IO，大幅提升查询性能。
建立联合索引时把查询字段全部包含进索引即可实现覆盖索引。

## 索引下推

索引下推（Index Condition Pushdown，ICP），MySQL5.6 之后支持。
在索引遍历阶段，直接在索引层过滤部分 where 条件，不需要回表之后再做过滤。
减少回表访问行数，降低 IO 开销。
索引下推（ICP）可以在存储引擎访问索引记录的过程中提前使用部分查询条件进行过滤，从而减少回表次数。
范围查询场景收益明显。

## 事务

事务是一组原子性 SQL 操作集合，要么全部执行成功，要么全部失败回滚。
事务具备 ACID 四大特性：原子性、一致性、隔离性、持久性。
InnoDB 支持事务，MyISAM 不支持事务。
事务存在并发问题：脏读、不可重复读、幻读，依靠隔离级别控制。

## MVCC

MVCC 多版本并发控制，InnoDB 实现高并发事务隔离的核心机制。
通过保存数据历史版本快照，实现读不加锁，读写不冲突。
依靠 Read View、Undo Log 版本链实现可见性判断。
主要用于 READ COMMITTED、REPEATABLE READ 隔离级别。
快照读使用 MVCC，当前读依旧需要加锁。

## Undo Log

Undo Log 回滚日志，保存数据修改前的旧版本数据。
作用 1：事务回滚，保证原子性，事务失败时利用 undo log 恢复数据。
作用 2：构建 MVCC 版本链，提供数据历史快照。
undo log 会被 purge 线程定期清理过期版本。

## Redo Log

Redo Log 重做日志，InnoDB 崩溃恢复核心。
记录数据页修改之后的物理变更。
事务提交时先写 redo log（WAL 预写日志机制），再刷盘脏页。
保证事务持久性，数据库宕机重启后，重放 redo log 恢复已提交事务数据。
有 redo log buffer、redo log file，支持组提交。

## MySQL 锁

MySQL 锁用于解决并发写冲突，保障数据一致性。
按粒度划分：

- 表锁：锁定整张表，开销小，并发差
- 行锁：InnoDB 行级锁，锁定行记录，并发高，只在当前读生效
行锁细分：共享锁 (S 锁)、排他锁 (X 锁)
意向锁：意向共享 IS、意向排他 IX，解决表锁与行锁冲突检测。
Gap 锁、Next‑Key 临键锁：RR 隔离级别下防止幻读。
锁会产生锁等待、死锁问题。
## Explain 执行计划

Explain 是 SQL 优化最常用的工具，可以查看查询的执行计划。

重点关注以下列：type 表示访问类型，从好到差依次为 system、const、eq_ref、ref、range、index、ALL；key 表示实际使用的索引；rows 表示预估扫描行数；Extra 中的 Using index 表示覆盖索引，Using filesort 表示需要额外排序。

## 慢查询优化

慢查询优化的常见手段：

1. 开启慢查询日志定位问题 SQL；
2. 为 WHERE、ORDER BY、JOIN 字段建立合适索引；
3. 避免索引失效的写法；
4. 大分页改用游标或延迟关联；
5. 只查询需要的列，避免 SELECT *。

优化顺序应该是先定位瓶颈，再针对性改写 SQL 或调整索引。

## MySQL 主从复制

MySQL 主从复制基于 Binlog 实现：主库将变更写入 Binlog，从库的 IO 线程拉取 Binlog 写入 Relay Log，SQL 线程重放 Relay Log 中的事件。

复制模式包括异步复制、半同步复制和组复制，异步复制性能最好但可能丢失数据，半同步复制要求至少一个从库确认接收。

主从复制是读写分离和容灾备份的基础。
