# 计算机网络技术知识库

## 计算机网络是什么

计算机网络是将地理位置不同的计算机通过通信线路连接起来，实现数据传输和资源共享的系统。

计算机网络的核心问题是：如何让数据在不可靠的物理链路上实现可靠、高效的传输。

## OSI 七层模型

OSI 七层模型从下到上依次是：

1. 物理层
2. 数据链路层
3. 网络层
4. 传输层
5. 会话层
6. 表示层
7. 应用层

OSI 是理论上的参考模型，实际互联网采用的是更简化的 TCP/IP 模型。

## TCP/IP 模型

TCP/IP 模型分为四层：

1. 网络接口层
2. 网络层，核心协议是 IP
3. 传输层，核心协议是 TCP 和 UDP
4. 应用层，包括 HTTP、DNS、SMTP 等协议

每一层只关注自己的职责，通过封装和解封装实现层与层之间的协作。

## TCP 三次握手

TCP 建立连接需要经过三次握手：

1. 客户端发送 SYN 报文，进入 SYN_SENT 状态；
2. 服务端回复 SYN + ACK 报文，进入 SYN_RCVD 状态；
3. 客户端发送 ACK 报文，双方进入 ESTABLISHED 状态。

三次握手的目的：确认双方的收发能力都正常，同时同步初始序列号，防止失效的连接请求突然到达服务端造成资源浪费。

## TCP 四次挥手

TCP 断开连接需要经过四次挥手：

1. 主动方发送 FIN 报文；
2. 被动方回复 ACK；
3. 被动方数据发送完毕后发送 FIN 报文；
4. 主动方回复 ACK，并等待 2MSL 后关闭。

四次挥手的原因是 TCP 连接是全双工的，两个方向的数据传输需要分别关闭。

主动方最后等待 2MSL 是为了保证最后一个 ACK 能够到达对方，并让旧连接的报文在网络中自然消亡。

## TCP 可靠传输

TCP 通过以下机制保证可靠传输：

1. 序列号与确认应答，保证数据不丢、不重、不乱序；
2. 超时重传，超过时间未收到确认则重新发送；
3. 快速重传，收到三个重复 ACK 立即重传；
4. 滑动窗口，实现流量控制，避免发送方淹没接收方。

## TCP 拥塞控制

TCP 拥塞控制用于防止过多数据注入网络，主要包含四个算法：

1. 慢启动，拥塞窗口从小值开始指数增长；
2. 拥塞避免，超过阈值后改为线性增长；
3. 快速重传，及时恢复丢失报文；
4. 快速恢复，配合快速重传降低窗口而不直接回到慢启动。

拥塞控制和流量控制的区别：流量控制是保护接收方，拥塞控制是保护整个网络。

## UDP 是什么

UDP 是无连接的传输层协议，只提供尽力而为的数据传输，不保证可靠性和顺序。

UDP 的特点是开销小、延迟低、无需建立连接，适合实时音视频、DNS 查询、游戏通信等场景。

## TCP 与 UDP 的区别

TCP 与 UDP 的主要区别：

1. TCP 面向连接，UDP 无连接；
2. TCP 可靠传输，UDP 尽力而为；
3. TCP 有流量控制和拥塞控制，UDP 没有；
4. TCP 面向字节流，UDP 面向报文；
5. TCP 只支持一对一通信，UDP 支持一对多、多对多。

## HTTP 与 HTTPS

HTTP 是超文本传输协议，默认端口 80，明文传输。

HTTPS 是 HTTP 加上 TLS 加密层，默认端口 443，提供加密传输、身份认证和完整性保护。

HTTPS 的握手过程：客户端获取服务器证书，验证证书合法性，协商对称密钥，之后使用对称加密通信。

HTTPS 结合了非对称加密（交换密钥、验证身份）和对称加密（传输数据）的优点。

## HTTP 状态码

HTTP 常见状态码分类：

1. 2xx 成功，例如 200、204；
2. 3xx 重定向，例如 301 永久重定向、302 临时重定向、304 缓存有效；
3. 4xx 客户端错误，例如 400 参数错误、401 未认证、403 无权限、404 资源不存在；
4. 5xx 服务端错误，例如 500 内部错误、502 网关错误、504 网关超时。

## DNS 域名解析

DNS 负责将域名解析为 IP 地址。

解析顺序是：浏览器缓存、操作系统缓存、本地 DNS 服务器、根域名服务器、顶级域名服务器、权威域名服务器。

DNS 查询分为递归查询和迭代查询，通常客户端到本地 DNS 是递归查询，本地 DNS 到各级域名服务器是迭代查询。

## 从输入 URL 到页面显示

从输入 URL 到页面显示的主要过程：

1. DNS 解析域名得到 IP 地址；
2. 与服务器建立 TCP 连接，HTTPS 还需完成 TLS 握手；
3. 发送 HTTP 请求；
4. 服务器处理请求并返回响应；
5. 浏览器解析 HTML，构建 DOM 树，加载 CSS 和 JavaScript，最终渲染页面。

## WebSocket

WebSocket 是一种在单个 TCP 连接上进行全双工通信的协议。

WebSocket 通过 HTTP 发起握手，升级协议后双方可以主动推送数据，适合聊天室、实时行情、在线协作等场景。

与 HTTP 轮询相比，WebSocket 避免了频繁建立连接的开销，实时性更好。

## Cookie 与 Session

Cookie 保存在客户端，由浏览器随请求自动携带，常用于身份标识和个性化配置。

Session 保存在服务端，通过 Cookie 中的 SessionId 关联用户状态，安全性更高，但分布式环境下需要 Session 共享方案。
